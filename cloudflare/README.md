# CP2077 port on Cloudflare (Worker + R2)

One Worker serves the page, the active engine bundle, the codec files and the original game files from one
R2 bucket on one origin. It sends COOP, COEP and CORP on every response. It mirrors `serve-engine-assets.py`:
single-range 206/416, ETag with If-Match (412), and prepared `.gz` for `engine-versions/<sha>/cp2077.{wasm,js,data}`
(served with `Content-Encoding: gzip` and `encodeBody: "manual"`).

**ETags.** For `/game/...` files, the size and ETag come from the stored manifest `runtime/game-files.json`.
That manifest is generated by `scripts/build-manifest.mjs` and is byte-identical to what the local server
produces. So R2's own etags never reach the runtime, and these three sources look identical to it: full
objects, partial-bucket block objects (`blocks/<key>/<n>`), and the dev proxy.

## Access gate (assets are CDPR / RAD copyrighted — never public)

- Every request needs the `cp2077_gate` cookie, which is HttpOnly, SameSite=Strict and Secure on https.
  `Authorization: Bearer <token>` also works.
- To get the cookie, open `/?key=<token>` once. The Worker sets the cookie and redirects to the same URL
  with `key` removed.
- Production fails closed: with no `ACCESS_TOKEN`, a token under 24 characters, or the dev token, it returns 503.
- **Cloudflare Access (recommended on top):** add a custom domain to the Worker. In Zero Trust, go to
  Access → Applications → Self-hosted, set that hostname, and add an allow policy for your email. Then set
  `workers_dev = false` in `wrangler.toml` so the `*.workers.dev` URL cannot bypass Access. Keep the token
  gate on as a second layer.

## Run locally (nothing uploaded)

```
cd D:\2077\cloudflare
npm install                                   # pinned wrangler 4.147.0, no login needed
node scripts/build-upload-list.mjs            # writes out/game-files.json + out/upload-list.json, prints size/cost
node scripts/upload.mjs --target local --max-mb 300 --execute --skip "^(game/archive/pc/content/|game/engine/|game/r6/|runtime/codec/bink/(lossless|predecoded)/[0-9a-f]+/frames)"
npm --prefix D:\2077\cloudflare run dev       # = wrangler dev --env dev on 127.0.0.1:8787, works from any shell
```

**Dev environment.**
- Local R2 lives in `.wrangler/state`.
- Objects that are missing locally (archives, videos) are proxied from `http://127.0.0.1:8078`, so
  `serve-engine-assets.py` must be running. The proxy is dev only (`DEV_MODE=1`); production never proxies.
- Each response is logged as `[cf] <status> <source> <path> <range> <ms>`. Source is `r2`, `r2-gz`, `block`,
  `blocks`, `proxy`, `manifest` or `edge-cache`.
- Re-seed after a new bundle is published: rerun the list script and the seed script.
- Upload-list check: any `[cf] ... proxy` line whose path is not under `game/archive/pc/content/`,
  `game/engine/`, `game/r6/` or `.../frames.*` is an object the real bucket would lack.

**Test URLs** (dev token `local-dev-gate`):
- Delivery smoke (no engine): `http://127.0.0.1:8787/cf-smoke.html?key=local-dev-gate`
  → console `CP2077 cfTest: PASS|FAIL ...`, `CP2077 cfTest: DONE pass=N fail=M`
- Game with trace: `http://127.0.0.1:8787/?key=local-dev-gate&assetTrace=1`
- Simulated WAN: add `&netDelay=80` (ms per response) and optionally `&netMbps=100`. The values persist as a
  cookie; `&netDelay=0` clears it. You can also set them with env `NET_DELAY_MS` / `NET_MBPS`.

## Asset trace (`?assetTrace=1`, any server)

`build/game/asset-trace.js` is loaded only when the page URL has `assetTrace=1`. It wraps main-thread XHR and
fetch, where the resource filesystem's synchronous 1 MiB Range reads happen. Every 30 s it logs:

- `CP2077 assetTrace: {...}`: totals, sync stall ms, stalls over 50/200/1000 ms, touched % of the manifest,
  per-file requests, MB, unique blocks and stall time, plus `runtimeMetrics` (from `cp2077ResourceFileMetrics`)
  as a cross-check.
- `CP2077 assetTrace ranges: {...}`: cumulative touched blocks per file, run-length encoded.

Not visible to the trace: Bink frame range fetches made inside the decoder worker.

## Deploy for real (you run these; the scripts never log in or touch credentials)

1. `npx wrangler login`
2. `npx wrangler r2 bucket create cp2077-assets`
3. `npx wrangler secret put ACCESS_TOKEN`. Use a long random value, at least 24 characters.
4. Objects larger than 300 MiB (7 of them: the archives and the largest videos) are over the
   `wrangler r2 object put` limit, so they go through rclone S3 multipart. Create an R2 API token
   (R2 → Manage API tokens, Object Read & Write on this bucket). Then run `rclone config`: new remote `r2`,
   type `s3`, provider `Cloudflare`, the token's key and secret, endpoint
   `https://<account_id>.r2.cloudflarestorage.com`.
5. `node scripts/upload.mjs --target remote` prints the plan as a dry run. Add `--execute` to upload.
   The upload is 76 objects, about 43.2 GB.
6. `npx wrangler deploy`, then open `https://<worker-host>/cf-smoke.html?key=<token>`.

**Cost** (R2 Standard list prices; verify on https://developers.cloudflare.com/r2/pricing/):
- Storage: about $0.50 per month (43 GB minus 10 GB free, at $0.015/GB-month).
- Upload: about 500 Class A operations, effectively free.
- Reads: one Class B operation per 1 MiB block, at $0.36 per million after the first 10 M per month.
- Egress: free.
- Workers: every block is also a Worker request. The free plan allows 100k per day; the paid plan is
  $5 per month including 10 M.
- `EDGE_BLOCK_CACHE=1` (the production default) caches blocks per colo through the Cache API. That only
  takes effect on a custom domain.

## Known risk: synchronous 1 MiB reads over WAN

Each cache miss is a blocking main-thread sync XHR. Read-ahead is one block, and only for sequential access,
with at most 2 pending. So every random read costs a full RTT plus the transfer time. For example, at 50 ms
RTT, 2,000 misses add about 100 s of main-thread stall. A sync XHR also has no timeout, so a hung request
freezes the tab.

Mitigations, in rising cost:
- (a) Use edge block cache and a nearby colo.
- (b) An opt-in JS XHR wrapper that widens a sync miss to N MiB and serves the following blocks from its
  own cache. This needs no relink.
- (c) Larger blocks and deeper or parallel read-ahead in `resource-filesystem-web.js`. That needs a new
  engine bundle.
- (d) Prefetch the trace's hot blocks asynchronously at boot, or into OPFS or the Cache API.

## Widened block reads / boot prefetch (`build/game/block-fetch.js`, opt-in)

The page loads `block-fetch.js` only when its URL has `blockFetch=` or `prefetch=`. It has two switches:

- `?blockFetch=N`: when a synchronous 1 MiB Range read misses, fetch N MiB (at most 64) in one request.
  - The extra blocks are kept in an LRU of 256 MiB by default; change it with `?blockFetchCacheMB=`.
  - Later sync reads, and the runtime's async read-ahead `fetch`es, are answered from that cache with
    synthesized 206 responses: the same ETag, `Content-Range` and x-user-defined text the runtime validates.
- `?prefetch=<same-origin url>`: at boot, warm the cache asynchronously with blocks from a trace.
  - The URL can point to a `cp2077AssetTrace.export()` JSON or to `out/partial-upload-list.json`.
  - Blocks are fetched in coalesced runs of at most 8 MiB, 4 at a time, up to 75 % of the cache.

Counters appear in the `blockFetch` field of `CP2077 assetTrace:`: `syncHits`, `syncMisses`, `fetchHits`,
`widenRequests`, `widenMb`, `prefetchMb`, `prefetchUsed`, `evictions`.

## Pthread resource reads: io variant bundle (`scripts/make-io-bundle.mjs`)

Archive reads happen in pthread workers. Each worker runs `CpResRead` from cp2077.js: a sync XHR in front of
its own 16 MiB LRU of 1 MiB blocks, with no read-ahead. The page-level hooks never see these reads.

- **The variant:** `node scripts/make-io-bundle.mjs` writes a NEW `engine-versions/<sha>/` bundle with only
  `CpResRead` replaced. The script refuses to run if the original function differs from the audited one.
  wasm and data are copied unchanged. It also writes the test page `build/game/native-browser-cfio.html`,
  served as `/runtime/native-browser-cfio.html`.
- **Getting switches to the workers:** the test page appends its own query to the cp2077.js URL. Each
  pthread worker is started from that URL and reads its switches from `self.location.search`.
- **Switches** (with none of them the reader behaves exactly like the base bundle):
  - `ioBlockMB=1..16`: block size, default 1.
  - `ioCacheMB=4..1024`: LRU size **per worker**, default 16.
  - `ioAhead=0..32`: extra blocks fetched in the same request on a miss, default 0.
  - `assetTrace=1` or `ioTrace=1`: workers post traffic to the main thread every 5 s.
- **Trace output:** the main thread logs `CP2077 ioTrace: {...}` and `CP2077 ioTrace ranges: {...}` every
  30 s, and `Module.cp2077IoTrace.export()` returns the same data.
- **Partial bucket:** `trace-to-ranges.mjs` accepts the ioTrace ranges lines. A wrangler dev log works too:
  `node scripts/wranglerlog-to-ranges.mjs wrangler.log`, then
  `node scripts/trace-to-ranges.mjs out/wranglerlog-trace.json --pad 0`, plus
  `node scripts/build-upload-list.mjs --no-game --out out/upload-list-nogame.json`.

## Production deploy (done 2026-10-20)

- Worker: `cp2077-port` on workers.dev, bucket `cp2077-assets` (private: no r2.dev, no custom domain).
- Secrets `ACCESS_TOKEN` (play gate) and `UPLOAD_TOKEN` (upload API) live in `.secrets.local.json` (gitignored);
  the phone/desktop link is in `PLAY-LINK.txt` (gitignored).
- Upload: `node scripts/upload-multipart.mjs` (resumable; `--verify` lists HAVE/MISS; log `out/upload-progress.log`,
  state `out/upload-state.json`). It goes through the Worker's `/__upload/` API, gated by `X-Upload-Token`.
  R2-only file overrides live in `out/r2-overrides/<key>` (the telemetry stub that disables the 127.0.0.1 sink).
- Checks: `node scripts/verify-prod.mjs`. Turn the upload API off afterwards with `npx wrangler secret delete UPLOAD_TOKEN`.
- The edge block cache (Cache API) is a no-op on workers.dev; it needs a custom domain.

## io2: shared block cache + async adaptive prefetch (`scripts/make-io-bundle2.mjs`, page `native-browser-cfio2.html`)

- **`ioShared=1`:** one SharedArrayBuffer block cache (`ioSharedMB`, default 256) shared by all pthreads.
  - Main thread posts the buffers to every pthread worker as that worker's first message.
  - A block in flight is fetched once; other threads `Atomics.wait` for it.
- **`ioPrefetch=K`:** read ahead asynchronously, but only after 2+ consecutive demanded blocks of one file in a thread.
  - Queues the next K blocks for `engine-versions/<sha>/cp2077-io-helper.js`, a dedicated worker with an idle event loop.
  - The helper fetches them with at most `ioInflight` (default 4) in flight.
  - Random reads stay single-block sync misses.
- **Bundle and trace:** source is `src/io-shared-cache.js` and `src/io-helper.js`. The bundle directory is
  versioned by both files. `CP2077 ioTrace:` gains a `shared` block.
- **Phones:** the shared cache is one allocation (not per worker); keep `ioSharedMB` at 64-128.

## io4: persistent cache + warm lists + sequential widening (`scripts/make-io-bundle4.mjs --base <engine>`)

Sources are `src/io4-cpresread.js` (pthread and main side), `src/io4-shared-cache.js` and `src/io4-helper.js`.
Everything in this section requires `ioShared=1`; defaults are unchanged.

- **`ioPersist=1` (`ioPersistMB`, default 4096, capped at 60% of free quota).** The IO helper keeps
  fetched blocks in OPFS under `cp2077-blocks-v1/`.
  - Storage is append-only 256 MiB `pack-N.bin` files plus two alternating `index-*.json` files.
  - Blocks are keyed by path + ETag + block, so a changed archive is never served stale.
  - A shared presence table lets a pthread miss ask the helper (over its own MessagePort) to fill the slot
    from disk. Network misses and large reads are handed to the helper and written to disk.
  - When over budget, the oldest pack is deleted. Without OPFS the tier switches off and reads go to the
    network.
- **`ioWarm=a,b` (`ioWarmInflight`, default 16).** At boot the helper downloads `/runtime/warm/<name>.json`
  block lists into the store in parallel, in recorded first-demand order. Lists come from
  `node scripts/make-warm-list.mjs <name> <console captures...>`, which reads the last
  `CP2077 ioWarm record:` line, recorded when `assetTrace=1` is set.
- **`ioSeqWiden` (default 4 in shared mode).** A sync miss inside a run of 3+ sequential blocks fetches up
  to 4 blocks in one request.
- **Stats:** `CP2077 ioTrace:` gives `shared.persist` (loadHits, writes, blocks), `shared.warm` and
  `widenedRequests`.

## io5 (`scripts/make-io-bundle5.mjs --base <engine>`, sources `src/io5-*.js`)

- **Repeat-visit leak fixed.** With `ioPersist=1`, large reads (512 KiB and up) take the block path:
  - blocks already on disk come from disk;
  - each missing run (up to 64 blocks, to the end of the read) is one block-aligned request, copied straight
    to the heap and persisted whole.
  - io4 sent large reads as one unaligned request whose edge blocks were never stored, so they were
    re-fetched on every visit.
  - The persist queue held while OPFS opens is bounded by bytes (512 MiB) instead of 64 entries.
- **Lifepath warming (`ioWarmLifepath`, on with ioPersist).** The engine prints
  `CP2077 missionflow: StartNewGame ... lifepathSpawnTag=#q000_<kid|nomad|corpo>` when New Game is
  committed. The main thread sees every pthread printErr line, so on that line the helper starts warming
  `streetkid`, `nomad` or `corpo`. Page scripts can also call `cp2077EngineModule.cp2077IoWarm(name)`.
- **Warm lists:** `make-warm-list.mjs` now defaults to `--max-mb 8192`, accepts record JSON (CDP dump of
  `cp2077EngineModule.cp2077IoTrace.record()`), and adds `--minus <list>` and `--intersect <list>`.

## io6 (`scripts/make-io-bundle6.mjs`, sources `src/io6-*.js`, lists `scripts/make-lifepath-lists.mjs`)

- **Boot warm:** with ioPersist, `ioWarm` defaults to `common` (`ioWarm=none` disables it). With
  `jump=newgame&lifepath=X` the bundle also warms X at boot.
- **Read-based lifepath detection (`ioWarmDetect`, `ioWarmDetectK=6`).** The helper loads
  `runtime/warm/lifepaths.json` (blocks recorded for exactly one lifepath). Once 6 of a lifepath's exclusive
  blocks are read (and it has at least 2x the next lifepath's count), it warms that list. The StartNewGame
  line remains the fallback.
- **Demand-following warm cursor.** Before each sync network miss a pthread sends the helper a `miss` hint.
  - If that block is ahead of the warm cursor, the cursor jumps past it; skipped chunks are retried at the end.
  - Chunks already on disk are skipped at fetch time.
  - Chunks are 4 blocks (`ioWarmChunk`).
- **Throttle:** `ioWarmBusyLanes=N` limits warm lanes while sync misses are in flight. It is off by default
  because it lost in the sim.
- **Lists:** `make-lifepath-lists.mjs --streetkid <rec> --nomad <rec> --corpo <rec>` writes `common`
  (blocks in all of them, in earliest-need order), `<lp>` (that lifepath minus common) and `lifepaths.json`.

## io7 (`scripts/make-io-bundle7.mjs --base <engine>`, sources `src/io7-*.js`)

- **Engine phases.** Every printErr line (main thread and pthreads) passes a watcher:
  - `CP2077 native state enter: <State>` marks the end of Initialization;
  - `session menu gate probe ... activeUI=3` marks the main menu being up.
  - Phases go to the helper and are recorded as `marks` in `CP2077 ioWarm record:`.
- **Boot warm (`ioWarmBoot`, default `boot,menu`)** starts at once. Until the engine reaches Running, at most
  `ioWarmBootLanes` (4) warm requests run, so boot demand misses are not starved.
- **Later warm (`ioWarm`, default `common-rest|common`, plus a jump lifepath)** starts when the main menu is up,
  or after `ioWarmDelay` seconds (45). `a|b` means the first of a, b that exists.
- **Lists:** `make-lifepath-lists.mjs ... --menu <io7 record of a fresh boot to the main menu>` writes `boot`,
  `menu` and `common-rest` (plus `common` for io6). Lifepath lists then exclude boot and menu blocks.
